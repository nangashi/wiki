# 委譲の実行手順

委譲を行うときに読む。記事の独立評価では、これに加えて対象wikiの評価プロトコルを読み、固有の入力・保存・停止条件に従う。役割・モデル・権限の正本は [サブエージェント定義](../.claude/agents/)。

## 役割選択と進行

- メインエージェント（Claude Code）が統括する。依頼の解釈、作業分割、採用・統合先の判断、成果物の最終確認、終了判定を担当する。
- 品質を維持しながら実行コストを抑えるため、作業に合う役割へ自律的に委譲する。独立評価など必須の分離を除き、依頼・確認の負担に見合う作業を委譲する。
- 狭い検索・候補抽出・資料整理は `finder`、指定範囲の執筆・修正は `editor`、独立評価・事実検証は `evaluator` のサブエージェントを使う。Agentツールの `subagent_type` に役割名を指定し、モデル・ツール制限は定義ファイルに任せる。
- wikiの手順が外部CLIの担当（例: insightの設計を書くCodex）を定めている場合は、その手順のコマンドを使う。外部CLIの出力はメインエージェントが検証・保存し、外部CLIにリポジトリの共有状態を更新させない。
- 単発コマンドは直接処理する。検索・抽出・執筆・修正は、下記の「小作業の直接処理」に該当すればメインエージェントが担当する。役割を毎回一式起動しない。機械検査は既存スクリプトを使い、モデルで再計算しない。
- 子には対象、必要な背景・制約・基準、編集可能なファイル、成果物、完了条件を含む自己完結した依頼を渡す。サブエージェントは会話履歴を引き継がずに起動する。同じ担当に続けて入力を渡す必要がある場合（insightの二段階評価など）だけ、SendMessageで同じエージェントを継続する。
- 子の報告は指定された出力schemaを優先し、必須項目を省略しない。指定がなければ結論、根拠の場所、変更ファイル、検証結果、未解決点を簡潔に返す。親は同じ探索を繰り返さず、判断に必要な原文と差分を確認する。
- 子からの再委譲は行わない。並行する子は最大3件。同じファイルへの書き込み担当は一人とし、index生成、評価manifestの更新は親が調整して直列化する。
- 子の結果が不十分なら不足箇所を絞って修正を依頼し、繰り返し失敗する判断はメインエージェントが引き取る。ただし独立評価が必要な場合は対象wikiの評価手順に従い、メインエージェントや執筆担当が判定や根拠を代行・補完しない。
- 委譲による総トークン削減は保証されない。重複読込、長い報告、不要な再試行を減らし、品質を保つ。通常報告に使用量の長い内訳を加える必要はない。

## 小作業の直接処理

次のすべてを満たす場合、finderやeditorへ委譲せずメインエージェントが直接処理する。

- 対象wikiの手順で、その作業自体に独立した担当・履歴の分離が要求されていない。
- 判断に必要な対象の原文・根拠・基準をメインエージェントが既に読んでいる。
- 対象と完了条件が限定され、追加の広い探索や複雑な統合を伴わず、依頼の作成・子の読込・結果確認より短く完了できる。

例は、読了済みの少数の短い記事からの根拠抽出、意味・根拠が確定した局所的な文章修正。記事数や修正項目数だけでは決めない。条件を満たすためだけに親が先に全資料を読む必要はない。

直接処理でも対象全体の確認と、対象wikiで要求される検査・変更後の独立評価・公開・停止条件は省略しない。必須の独立調査・評価・外部検証にはこの例外を適用しない。

サブエージェントの権限は実行環境の制約にも従う。
