# ADR 0001: リポジトリを共有し、wikiの運用定義を独立させる

- 状態: 採用
- 決定日: 2026-09-05
- 現行仕様: [Wiki接続仕様](../wiki-contract.md)

## 背景

insightは未知ケースの推論に使える概念を育て、itは技術の体系的理解・採用判断・運用知見を集約する。粒度、情報を増減する判断、出典形式、評価・公開条件が異なる。schemaは既に分かれていたが、共通スキルとlint実装にはinsightの評価・改善が入り込み、itの基準もreview-pageとエージェント定義へ分散していた。

2026-09-05の検討時、記事ファイルはinsight 75件、it 15件、明示的な越境リンクは5件・4記事ペア。ADRと問題軸選定など有用な接続はあるが、これは利用頻度や同居による効果の測定ではない。知識が自然に結びつくことより、検索・リンク解決・index生成の保守共有を同居の実益と判断した。

## 決定

リポジトリと記事・評価履歴の位置を維持する。共通スキルは登録・設定を通して対象wikiの手順を読む。採用・執筆・評価・公開条件、固有検査はwikiが所有する。共通ツールは現在共有するMarkdown・index・リンク形式を扱い、wiki名や固有の評価尺度で分岐しない。

AGENTS.mdは日常作業の入口と短い共通方針、接続仕様は現在の契約、ADRは判断理由と再検討条件を持つ。品質基準や実行手順をAGENTS.md・ADR・モデル役割へ複製しない。子ディレクトリのAGENTS.mdの自動読込に依存せず、設定から必要な文書を明示的に読む。

ingest/query/review-page/lintの入口を維持する。insightのlintは引き続き必要な独立再評価・改善まで進むが、その定義はinsight側へ移す。it単独操作ではinsightの評価を起動しない。queryは必要な横断検索を保つ。

## 比較した案

| 案 | 判断 |
|---|---|
| repoを分離する | 現時点では見送る。運用基盤を共有でき、分離しなくても品質方針を独立させられる |
| schema・基準だけを分ける | 不十分。操作手順とスクリプトの固有依存が共通側へ残る |
| 全wikiで同じ評価方式を使う | 採用しない。記事の目的と成熟のさせ方が異なる |
| 今回の構成 | 採用。共通化する範囲を形式と入口に限定し、wikiごとの変更を局所化する |

## 結果と負担

設定・手順への参照が増えるため、入口と読み込み条件を明示し、参照先と機械的な契約をテストする。手順の見落としを避けるために毎回全wikiを読み込む運用へは戻さない。共通コードのPython 3.8互換にはTOMLパーサーを同梱し、独自の簡易構文を作らない。

評価helperはinsight専用のまま移し、rubric、記事target、hash、評価履歴形式を変えない。ツール移行を理由とする記事の書き換えや全件再評価を避ける。過去のsuggestions・評価記録にある旧パスは当時の記録として保持する。

## 再検討条件

- 一方の運用変更が繰り返し他方へ影響し、境界の修正でも解消しない。
- 公開先・権限・履歴・作業キューを別々に管理する必要が生じる。
- 横断利用と共通基盤の保守の利点より、各repoの単純さが優先される。

repo分離を再検討するときも、今回独立させたwikiの運用定義を移行単位とする。
