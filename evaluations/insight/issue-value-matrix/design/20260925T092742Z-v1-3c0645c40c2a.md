# Insight設計評価: issue-value-matrix
- reusability_gate: 合格

## 再利用性ゲート
- R1: 合格。二軸（今答える必要性、答えの明確さ）と三条件を使えば、原典にない仕事でも現在地を判断できる。つまり、問いを選び直すか、分析を磨くか、探索へ戻るかを決められる。設計のD2・D3・D5と、第5節の顧客調査の仮想例がこの推論を求めている。
- R2: 合格。固有名を除いても構造が残る。「問いの必要性」と「答えの明確さ」は独立して不足しうる。作業量はどちらも直接には高めない。問いを選ぶ前に作業を積む経路は、判断に寄与しない分析を生む。役割を置き換えれば、別の調査や分析にも当てはめられる。
- R3: 対象外（異領域への一般化を採用の理由にしていない）。採用・省略に「異領域への普遍性は採用理由にしない」と明記されている。
- R4: 十分。境界を多く示している。積は概念上の表現にとどめ、数値採点に使わない。二軸は統計的に独立とは言わない。高・高の領域でも成果は保証しない。低・低の領域でも即停止を命じない。ほかに、回答不能な問いの分割・保留、学習の副次的価値、探索と犬の道を作業の役割で区別する点が書かれている。

## 観点別評価
| 観点 | 状態 | 根拠 |
|---|---|---|
| 読者・目的 | 十分 | 読者の状況が具体的である（「精巧な分析や資料を作っても判断が進まず、さらに調査や作り込みを足そうとしている読者」）。使い道も三つの判断（問いの再選択／分析を磨く／探索へ戻る）として書かれている。努力や学習の価値を否定しない限定もある。統合の決定も妥当である。原著では、犬の道はこのマトリクス上の経路として説明されている（下記P1の出典を参照）。独立記事にすると、二軸の定義と三条件の点検が重複する（現行inu-no-michi 37-43行と現行issue-value-matrix 30-38行）。 |
| 読後の到達点 | 十分 | D1〜D5は、どれも「説明／見分け／判断」の形で書かれ、内容表のどこかの節に対応している。統合元の独自内容のうち、失敗経路はD4、探索との区別はD4・D5に残っている。旧設計のD1〜D3（wiki/insight/designs/inu-no-michi.md 9-11行）は落ちていない。 |
| 内容と順序 | 十分 | 順序は、定義→現在地の診断→経路→選ぶ基準→適用例→探索と境界である。各節の役割も分担が決まっている（第3節末「四領域が『今どの状態か』、本節が『何を後回しにして進んでいるか』」）。三条件と実務の確認質問は一つの表にまとめ、チェックリストの重複を避けている。統合元の「3つの点検項目」（inu-no-michi 39-43行）もこの表に吸収されている。 |
| 主張と根拠・境界 | 要対応 | 解の質の定義は原著どおり「明確さ」までにしている。「裏付け」を加えない点は、確認記録（research-issue-value-matrix-external.md 14-29行）と合っている。S5・S7の題名は、現行記事の誤った題名から実際のページ題名へ直されている（1101.com：「『イシューからはじめよ』のまわりで考える。」第1回。note：「圧倒的に生産性を高める、深い仮説の生み出し方」をWebFetchで確認）。S6について設計が書く支持範囲は、公式紹介の文言と合っている（「気合いと根性で手当たり次第に始める『犬の道』」「『いま本当に答えを出すべき』かつ『答えを出す手段がある』問題は、ごくわずか」）。ただし第2節の軸の向きと、犬の道を領域の呼称として扱う点は、確認できた原著引用と合わない（P1）。 |
| 採用・省略 | 十分 | 比較（四領域・経路・探索）は、診断・経路・見分け方の三役に分けてあり、重複しない。顧客調査の適用は仮想例と明記され、行動指針は条件で分岐する（「問いが必要なら…必要性が不明なら…候補自体が不明なら…」）。本質的問題の割合、作業削減率、成功確率、出典未確認の警句を省く理由は妥当である。旧設計が「100分の1」を効果量としない判断も引き継がれている。関連リンクを二つに絞った理由もある。 |

## 対応項目
### P1: マトリクスの軸の向きと「犬の道」の位置づけを原著に合わせる
- 種別: 修正必須
- 観点: 主張と根拠・境界
- 対象箇所: 「横軸を解の質、縦軸をイシュー度と明示する。」「低・高の領域に『犬の道』の呼称を添える。」
- 問題: 原著の定義と犬の道の説明を引いた二次資料が二つあり、どちらも横軸（ヨコ軸）をイシュー度、縦軸（タテ軸）を解の質としている。犬の道も「労働量によって上に行き、左回りで右上のバリューある領域に到達しようとする」経路として引かれている（https://shoji-rmc.com/1283/ 、https://note.com/uiuxdesigin_hiro/n/ne35ddef65a1d をWebFetchで確認）。設計は軸を逆にしたうえで、S1を二軸モデル・犬の道の出典にしている。このままでは、読者が原著と逆の図を原著のものと受け取る。また、犬の道を一つの領域の名前として示すと、第3節とD4の「経路」という定義と食い違う。読者は「解の質が高くイシュー度が低い状態＝犬の道」という固定した分類で覚え、低・低から作業量で上がっていく途中の段階を見落とす。表記「高・低」「低・高」も、どちらの軸の値かが書かれておらず曖昧である。
- 改善後に満たす条件: 軸の向きを原著どおり（横＝イシュー度、縦＝解の質）にする。原著と違う向きを採るなら、記事側の作図だと明記し、S1には帰属させない。犬の道は四領域の一つの名前にせず、「解の質を先に上げ、後からイシュー度を上げようとする経路」として示す。領域はその経路が通る場所として触れる程度にとどめる。四領域の表記は、どちらの軸の値かが明確になっている。
- 対応方法: 第2節の軸の指定を直し、「低・高の領域に犬の道の呼称を添える」を削る。そのうえで、第3節の経路と第2節の領域の関係を一文加える（例：経路は低・低から解の質方向へ進む）。可能なら原著の図（旧版p.25〜26付近）を直接確認し、S1の確認範囲に軸の向きも加える。確認できなければ、二次引用で確かめた範囲だと境界欄に記す。

### P2: 顧客調査例の三つの場合の対応づけを明確にする
- 種別: 任意改善
- 観点: 内容と順序
- 対象箇所: 「前者は問いの必要性を確認し、中者は候補を区別する情報を集め、後者は探索で問いを具体化する。」
- 問題: 三つの場合を「前者・中者・後者」で指しているため、どの場合がどの対応に当たるかを読み取りにくい。四領域や犬の道の経路との対応も書かれていない。
- 改善後に満たす条件: 三つの場合それぞれに、第2節の領域（または第3節の経路／第6節の探索）と、取るべき対応が一対一で書かれている。
- 対応方法: 三つの場合を名前付きで並べ、それぞれに「現在地」「次の行動」を添える。

### P3: 統合で残る被リンクの扱いを作業手順で確保する
- 種別: 任意改善
- 観点: 採用・省略
- 対象箇所: 「統合元`[[inu-no-michi]]`へのリンクは残さない。」
- 問題: `inu-no-michi` へのリンクは、対象記事以外にもある（wiki/insight/pages/pre-analysis-output-design.md、wiki/insight/pages/proxy-metrics-knowledge-work.md、wiki/insight/pages/quadrant-ii-principle.md、wiki/insight/index.md）。統合元を削除するとこれらは切れたリンクになる。これは設計の品質そのものの問題ではなく、統合作業の漏れのおそれである。
- 改善後に満たす条件: 統合元を削除する時点で、上のリンクがすべて `issue-value-matrix`（必要なら該当節）へ付け替えられているか、削除されている。
- 対応方法: 設計本文には書かず、統括の統合作業と機械検査（リンク検査）の中で処理する。

## 良い点
- 解の質の原著定義を「明確さ」までにとどめ、根拠の確認や代替説明の比較を記事側の提案として分けている。確認記録で誤りとされた「裏付け」の付け足しを明示的に禁じている。
- 統合元の独自内容のうち、探索と犬の道の違いを作業の役割で区別する点は第6節とD4に残っている。問いの選択より作業を先に進める失敗経路は第3節とD4に残っている。重複していた点検項目は三条件の表にまとめられている。
- 積の表現、二軸の独立性、高・高／低・低の各領域の解釈について、短絡的な読み方を具体的に禁じている。「今必要か」を原著の第四条件にしないなど、原著と記事側の操作化の境界がはっきりしている。
- 資料のS IDを維持している。統合元S4を統合先S6へ対応させている（同じ英治出版のページ）。S5・S7の題名を実際のページ題名に直している。
