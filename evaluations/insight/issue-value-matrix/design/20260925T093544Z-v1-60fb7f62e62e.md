# Insight設計評価: issue-value-matrix
- reusability_gate: 合格

## 再利用性ゲート
- R1: 合格。二つの軸で「問いの必要性が足りない」のか「答えの明確さが足りない」のかを分けて点検し、元資料にない仕事でも次の行動を判断できる。次の行動は、問いの選び直し、分析、探索のいずれか。到達点D2・D4・D5と顧客調査例の三つの場合（設計38〜40行）が、未知のケースでの判断として書かれている。
- R2: 合格。固有名を外しても次の構造が残る。二つの軸（今答える必要性と答えの明確さ）、その積による点検、進める順序の違い（解の質を先に上げる経路とイシュー度を先に上げる経路）、探索と犬の道を分ける基準（未確定事項と見直し時点）。
- R3: 対象外。設計71行で「異領域への普遍性は採用理由にしない」と明示しており、同じ領域の調査・分析で使い回す前提である。
- R4: 満たす。設計59〜66行と73行に適用条件と例外がそろっている。積は点検用の概念表現であること、二つの軸は統計的に独立ではないこと、領域と経路の区別、回答可能性が期限と資源に依存すること、学習の副次的価値、探索との区別である。

## 対応項目
### P1: 探索の見分け基準を適用例より前に置く
- 種別: 修正必須
- 観点: 内容と順序
- 対象箇所: 「5 顧客調査への適用」の後に「6 健全な探索との違いと適用の境界」／「原因候補を探す初期調査 | 第6節の探索。」
- 問題: 第5節の例は三つ目の場合を「第6節の探索」に分類し、次の行動として「未確定事項と見直す時点を置いて」と書いている。しかし、探索と犬の道を分ける基準（何が未確定か、何を知れば問いを更新できるか、いつ見直すか）は第6節まで説明されない。このため読者は、一つ目の「用途未確認の集計追加」と三つ目の「原因候補を探す初期調査」を分ける根拠を知らないまま分類を受け入れることになる。例がD4（探索と見分けられる）の達成を確かめる役割を果たせない。
- 改善後に満たす条件: 顧客調査の三つの場合を示す前に、探索と犬の道を分ける基準（作業の役割、未確定事項、見直し時点）が本文で説明されている。例は、既に示した基準を当てはめて分類する構成になっている。
- 対応方法: 第6節の「健全な探索との違い」の部分を第5節の前に移す。つまり第3節の直後、または第4節の直後に置く。例の後には適用の境界（往復、回答不能な問いの分割、学習の副次的価値）だけを残す。表中の節番号の参照もそれに合わせて直す。

### P2: 「左回り」を反時計回りと言い換えないよう指定する
- 種別: 任意改善
- 観点: 内容と順序
- 対象箇所: 「まず上方へ進み、その後に右上を目指す「左回り」の経路として示す。」
- 問題: 横軸がイシュー度で右ほど高く、縦軸が解の質で上ほど高い図では、左下から上へ進んでから右へ移る動きは幾何学的には時計回りになる。執筆時に「左回り（反時計回り）」と補うと、図の説明と矛盾する。
- 改善後に満たす条件: 「左回り」は原著由来の呼び名で、左側を回って上へ進む経路を指すと分かるように書かれている。回転方向の言い換えは付けない。
- 対応方法: 第3節の設計に「左回りは図の左側を経由する意味で使い、時計回り・反時計回りの言い換えはしない」と一文加える。

### P3: 解の質の定義の確認経路を永続的に参照できるようにする
- 種別: 任意改善
- 観点: 主張と根拠・境界
- 対象箇所: 「旧版p.26の解の質の定義は、問いへの答えの明確さとして扱う。」
- 問題: 現行記事の「検証された答え」という定義を改める根拠は、一時ファイルの確認記録と、設計に書かれていないp.26引用ブログにしかない。S5本文の抜粋は環境によって読めない場合がある。そのため、後の評価者がこの定義をどこで確認したのか追いにくい。
- 改善後に満たす条件: p.26の定義文を確認した資料、または永続パスにある確認記録を、設計から辿れる。
- 対応方法: 確認記録を `evaluations/insight/issue-value-matrix/` 以下に保存して、その永続パスを設計のS1行の境界欄に書く。または、p.26を明記した引用資料をS1の確認範囲に加える。

## 良い点
- 現行記事にある軸の取り違えを解消している。現行記事は右下を犬の道、左上を高イシュー度としていた。設計は軸の向きを明示し、「軸名を省いた『高・低』表記を使わない」と定めているので、同じ誤りの再発を防げる。
- 「犬の道は四領域の一つの名前ではない」と、領域（現在地）と経路（進め方の順序）を分けている。この区別があるので、左上にいることだけでは犬の道と判定できないことを読者に示せる。
- 顧客調査例の一つ目「用途未確認の集計追加」で、「必要性が未確認なだけではイシュー度が低いと断定せず」としている。集計が精巧というだけで左上に置いてしまう誤分類を防いでいる。
- 三条件の表を「原著の条件」と「記事側の確認質問」の列に分け、「今必要か」を原著の第四条件にしないと明記している。原著に書かれていることと記事側の提案の区別が保たれている。
- 統合元の本質的な内容を落としていない。経路比較、探索との区別、点検3項目、「作業量や網羅性が進捗の代わりになる」という機序は残っている。統合元の根拠のない数値や警句を省く理由も明示されている。
