# /query スキル

wikiを検索して質問に答える。wikiに情報が不足している場合はWebで補完し、新たな知見があればwikiへの追加を提案する。

回答は草稿を作ったあと、**根拠検証**（新しいコンテキストのサブエージェント）と**自己チェック**（構造化）を経て仕上げる。

## 事前準備

`wiki/collections.md` を読み、コレクション定義を確認する。

---

## 処理フロー

### ステップ1: wikiを検索する

1. `wiki/insight/index.md` を読み、ページ一覧を把握する
2. 質問に関連しそうなページを特定する（スラグ名・index のサマリからあたりをつける）
3. 関連ページを `Read` で読み込む
4. 関連ページからさらにリンクされているページも必要に応じて読む

### ステップ2: wiki情報で回答できるか判断する

**wikiで十分な場合**（以下をすべて満たす）:
- 質問の核心部分をwikiが直接カバーしている
- 情報が具体的で、あいまいな記述でない
- 追加の文脈なしに理解できる

→ **ステップ3（Wiki回答）** へ

**Webを使う場合**（いずれかに該当）:
- wikiに該当概念のページがない
- wikiにページはあるが情報が不足・断片的
- 最新情報が必要な質問

→ **ステップ4（Web補完）** へ

### ステップ3: wikiから回答する

wikiの情報をもとに回答を構成する。引用元のページを `[[スラグ]]` で明示する。

その後、**ステップ5（根拠検証と自己チェック）** へ。

### ステップ4: Webで情報を補完する

1. 質問に関連するキーワードで `WebSearch` を実行する（1〜3回）
2. 得られた情報を統合して回答する
3. 参照したURLをリストアップする

その後、**ステップ5（根拠検証と自己チェック）** へ。

### ステップ5: 根拠検証と自己チェック

**(a) 根拠検証**（新しいコンテキストのサブエージェント）

草稿を書いた文脈を持たない検証者に、根拠のない主張を洗い出させる。`Agent` ツールで新規サブエージェントを起動する（`subagent_type: "fork"` は使わない。fork は草稿作成の文脈を引き継ぐため独立しない）。プロンプトには以下だけを渡す:

```
以下はwikiクエリへの回答草稿です。草稿が引用しているwikiページ（[[スラグ]] → wiki/insight/pages/<スラグ>.md）を読み直し、
そのページに根拠がない主張を洗い出してください。

- 出力は指摘のリストのみ。草稿の書き直し・補足・新しい主張の追加はしない
- 各指摘: 「草稿の該当文」/ 引用されたページ / 判定（根拠なし・ページの記述と食い違い・ページより強い断定）/ 根拠になりそうなページ内の記述（あれば）
- Webで補完した主張（URL出典）は対象外。wikiページを根拠にしている主張だけを見る
- 指摘がなければ「指摘なし」とだけ返す

## 草稿
{draft}
```

返ってきた指摘ごとに、草稿の主張を削除・弱化するか「wiki外の知見」と明示する。採否と理由を控えておく（出力形式の「検証で除外・修正した主張」に載せる）。

**(b) 自己チェック**（本体セッション）

1. 並列列挙を因果連鎖・階層構造に組み替える（「AがあるからBが起き、だからCする」の形にできないか）
2. 草稿が見落とした上流の問い・視点・関連wikiページがないか `wiki/insight/index.md` を見直し、あれば追加する
3. 各節が「なぜ」を説明しているか確認し、不十分なら補強する

完了したら**ステップ6**へ。

### ステップ6: 最終出力を構成する

草稿（ステップ3/4）に根拠検証の反映と自己チェックの再構成（ステップ5）を加えて最終回答を出力する。

その後、**ステップ7（wiki追加判断）** へ。

### ステップ7: wikiへの追加を判断する

**以下のいずれかに該当する場合のみ** wiki追加を提案する:

| 追加が必要な状況 | 説明 |
|----------------|------|
| **新たな知見** | wikiに存在しない情報・概念・事実が得られた |
| **ページ間の新接続** | 既存の2つ以上のwikiページが実は関連していることが判明した（リンク未設定） |
| **既存ページの補強** | 既存ページの説明に重要な補足情報が加わる |

追加を提案する場合、`wiki/collections.md` の判定目安に照らした判定結果も提示する。

**追加不要な場合** (提案しない):
- 単純にwikiの内容を言い換えただけ
- 質問への直接回答だが、wiki的な知識としての独立性がない（例: 「〇〇の設定コマンドは？」）
- 既にwikiに記録済みの内容

### ステップ8: wiki追加を実行する（提案が承認された場合）

ユーザーが追加に同意した場合、`wiki/insight/schema.md` の **「共通書き込み手順」** に従ってwikiページを作成・更新する。

---

## 出力形式

```
## 回答

<根拠検証・自己チェックを経た回答本文>

参照: [[スラグ1]], [[スラグ2]]（wikiから回答した場合）
参照: https://url （Webから補完した場合）

---

## 検証で除外・修正した主張（該当する場合のみ）

- 「草稿の該当文」 → 除外 / 弱化 / wiki外の知見と明示 — 理由（引用ページに根拠なし 等）

---

## wiki追加の提案（該当する場合のみ）

以下の知見をwikiに追加することを提案します:

### 提案1: [新規ページ or 追記] — タイトル
**理由**: 新たな知見 / ページ間の新接続 / 既存ページの補強
**内容**: <追加する情報の要約>
**対象**: [[スラグ]]（追記の場合）

---

追加しますか？（「はい」で実行、「いいえ」でスキップ）
```

ステップ8でinsightページを新規作成または更新した場合、完了報告に次の1行を加える。自動同期はしない。

```markdown
Anki同期: `/anki` で新規・変更ページを検知し、カードへの反映案を確認できます。
```

---

## 注意事項

- 回答の質を落としてでもwikiに情報を詰め込もうとしない
- Webの最新情報とwikiの情報が矛盾する場合は、その矛盾をユーザーに伝える（`/lint` の実行も提案する）
- ステップ5は回答の正確さと構造を高めるためのもの。根拠検証で主張を除外した結果、回答の結論が変わった場合はその理由をユーザーに簡潔に説明する
