# 取り込みブリーフ様式（Muse → /ingest ブリーフ入力モード）

Muse が一次資料を調査して作成し、`.tmp/briefs/<YYYY-MM-DD>-<topic-slug>.md` に置く。Claude Code は `/ingest brief:<パス>` でこれを読んで執筆する。

## ルール

- **本文案は書かない。** 核心文と骨格（見出し案）までに留める。執筆は Claude Code が行う
- **言語は日本語。** 原典の引用・固有名・論文名は原語のままでよい
- **一次資料は実際に取得して読んだものだけを挙げる。** 検索結果のスニペットや他資料の孫引きだけで確認したものは載せない
- 以下の見出し6つはすべて必須。1つでも欠けると `/ingest` は停止する。見出し名を変えないこと
- 取り込み判定はユーザーの承認を得てから記入する（Muse が自分で承認者にならない）

---

## テンプレート（ここから下をコピーして埋める）

```markdown
- 対象トピック: <トピック名>
- ソース種別: <Webページ / PDF / 本 / トピック>
- 作成日: <YYYY-MM-DD>
- 作成者: Muse

## 核心文
<このトピックの本質を一読で理解できる1文（目安: 読点2〜3個・80字以内）。圧縮で失われるニュアンスは直後の補足1文で補ってよい>

## フレーム根拠
<なぜこのフレームが正確か。どの一次資料のどの記述に基づくか>

## 骨格
- <節名>: <その節で何を述べるか（1行）>
- <節名>: <…>

## 弱点・要補強点
- <確認できなかった点・補強が必要な点。Claude Code に追加調査させる具体的な項目として書く>

## 参照した一次資料
- 階層: <一次 / 二次 / 三次>
  - sources 表記: <ページの sources に入れる文字列（例: "https://..." / "book:書名（著者名）" / "file:<ファイル名>"）>
  - 確認内容: <この資料で何を確認したか>

## 取り込み判定
- 判定: <YES / NO / 候補> — <理由（wiki/collections.md の判定目安に照らして）>
- 承認者: <ユーザー（承認日時・承認経路）>
```
