# itの監査

`../schema.md` と [記事品質基準](../references/article-quality-rubric.md) を読む。共通lintの構造診断、全対象ページの意味的な重複・矛盾監査結果を使う。固有の機械検査・評価履歴の自動再評価は定義しない。

- `LARGE`や文字数だけで分割せず、1技術1ページへの集約を優先する。
- 同一技術の個別事例は既存技術ページへの統合候補にする。独自情報・検索入口・条件差を確認する。
- I1〜I4で理解の自立性、運用移転性、リンク、統合・分割を確認する。機械検査が候補にしなかった記事も意味的監査から除外しない。
- 矛盾は環境・バージョン・制約差を先に確認する。未検証ならどちらが誤りか断定しない。
- 改善の優先順位・更新・報告は [review.md](review.md) に従う。統合・分割・削除・リダイレクト化は具体案を示して個別確認する。既に承認された修正は再確認しない。

対象、根拠、推奨対応、実施結果、残課題を報告する。該当なしも明記する。変更した場合だけ `python3 tools/wiki/wiki_structure.py index --collection it` でindexを生成する。
