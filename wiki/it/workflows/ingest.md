# itへの取り込み

`$ingest`から実行する。queryで追加が承認された場合もingestへ引き渡す。

## 条件付き参照

- **採用判断で読む文書**: `../schema.md` の記事単位・粒度の規定。`$query` はこの採用判断部分とここで指定された基準だけを読む。
- **執筆時**: `../schema.md` と `../references/article-quality-rubric.md`。
- **評価時**: `../references/article-quality-rubric.md`。

### ステップ1: 既存ページを把握する
`wiki/it/index.md` を読み、すでに存在する技術ページとその内容を把握する。

### ステップ2: 対象の技術・パターンを特定する
ソースが扱う技術・パターンを列挙する。

- 1つのソースが複数の技術に触れる場合は技術ごとに分割する
- 記事の主題だけでなく、途中で語られる別技術の判断材料（比較・失敗談・ベンチマーク等）も取り込み対象になりうる

### ステップ3: 技術ごとに統合先を判断する

```
対象技術の既存ページがある？
  YES → 既存ページに統合（追記）
  NO  → 1技術1ページの単位として独立したページを作る価値がある？
    YES → 新規リファレンスページを作成
    NO  → 最も関連する技術ページの該当セクションに追記。
          どのページにも収まらない場合のみ事例型ページを提案（ユーザー確認）
```

### ステップ4: ページを書く・更新する

**追記の場合（標準ルート）:**
- 新しい情報を該当セクションにマージする。セクションがなければフォーマットの順序に従って追加する
- **矛盾チェック**: 既存の記述と矛盾する場合、(a) 条件・環境が違うなら条件を明記して併記、(b) 既存情報が古い・誤りなら更新。判断できない場合はユーザーに確認する
- 追記後にセクション全体を読み直し、時系列の継ぎ足しではなく1つの記事として流れるように整える（「なお」「また」の連鎖は書き直しの兆候）
- `updated` を今日の日付に更新し、`sources` に新しいソースを追加する

**新規の場合:**
- 命名規則に従い `wiki/it/pages/<slug>.md` を作成
- frontmatter: title・type・sources・created・updated を記入
- 本文: リファレンス型フォーマットに従う（埋められるセクションだけでよい）

#### 草稿・改稿後の確認

新規・追記とも、執筆担当が次を確認してから品質確認へ進む。

- 各節が読者のどの問いに答えるかを確認する。比較表・採用条件・アンチパターンなどで同じ判断と理由を繰り返している場合は、参照しやすい一か所へまとめるか、各節で異なる判断材料を示す。概要の要約や、条件を説明するために必要な再提示は残す。任意の節をすべて埋めたり、節数や文字数の削減を目標にしたりしない。
- 改稿した箇所は前後を照合し、適用条件、因果の向き、断定の強さ、数値の単位・起算点・回数の数え方が意図せず変わっていないか確認する。統合・削除した場合は、正常時と条件が変わった場合の動作、設定が許す範囲と禁じる範囲など、判断に必要な分岐が残っているか確認する。元の主張に誤りが見つかった場合は根拠に基づいて修正し、具体化のために未確認の原因や結果を補わない。

問いを公開本文の見出しにしたり、確認メモを保存したりする義務は設けない。

### ステップ5: 品質確認
記事品質基準のリファレンス型の2条件を確認する。未達の場合は補足調査を提案する:

```
### 品質確認: [[スラグ]] — タイトル

以下の点で情報が薄い状態です:
- （未達の条件とその根拠）

補足調査を行いますか？（キーワード案: 「...」「...」）
```

- ユーザーが承認した場合: その場で 利用可能なWeb検索 を実行し、ページを更新してから次のステップへ進む
- ユーザーが断った場合: そのまま保持し、ステップ8のサマリに「補足調査未実施」として記録する
- 品質が十分な場合: このステップは何も出力しない

### ステップ6: 関連リンクを張る
- 新規・更新ページの「関連」セクションに、理解や判断に役立つ関連技術へのリンクを追加
- 相互リンクは必須にしない。関連先からも独自の説明が必要な場合だけ、そのページを更新する
- insightコレクションに関連する洞察があれば `[[insight:slug]]` で参照する
- 共通スキルが取得した被リンクを参考にする

### ステップ7: 共通スキルへ引き渡す
変更記事、根拠の場所、公開／保留、残課題を共通スキルへ返す。index更新と被リンク取得は共通スキルが実行する。

### ステップ8: 作業サマリを出力する
以下を報告する:
- 新規作成したページ一覧（タイトル・スラグ）
- 更新したページ一覧（タイトル・追記セクション・内容の要約）
- スキップした情報（理由付き）
- 追加した関連リンク
- 補足調査未実施のページ（ユーザーが断った場合のみ）
- 変更記事と根拠の場所、公開／保留、残課題
