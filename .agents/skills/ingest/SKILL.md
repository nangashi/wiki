# $ingest

新規記事と既存記事への情報追加の入口。入力はURL、PDF、`本:` / `book:`、`トピック:` / `topic:`、および任意の対象wiki指定。

## 対象の選択と読込

1. `wiki/collections.toml` から設定の所在を取得する。対象指定があればその設定だけを読み、未指定なら各設定の `purpose` で候補を絞る。
2. ソースのタイトル・概要から候補を選び、候補の `workflows.ingest` の採用判断部分と、そこで指定されたschema・採用基準を読み、採否を判断する。既存の指定・承認を優先し、追加先が実質的に曖昧な場合だけ確認する。
3. 採用後は選択したwikiの `schema` と `workflows.ingest` に従い、執筆・評価の各段階に入るときに指定文書を読む。他wikiの執筆・評価文書は読まない。

設定内の文書パスは設定ファイルのディレクトリ基準。コマンドはリポジトリルートで実行する。設定・手順が欠けている場合は推測した基準で書き込まず、欠落を報告する。

## 実行

- Web・PDFは本文を確認する。書籍・トピックは原典・著者・公式資料を優先し、必要な根拠が揃うまで調査する。検索指示自体を出典として扱うかは対象wikiのschemaに従う。
- 対象wikiのindex・記事を検索し、新規／追記／スキップ候補を作る。粒度・統合・採用の判断は対象wikiの基準を使う。
- 複数入力は順に処理する。複数wikiへ取り込む場合は、それぞれの独自の貢献を確認し、同内容を自動で二重保存しない。
- `workflows.ingest` に従って調査、執筆、必要な検査・評価・改善、公開判断まで実行し、変更対象、検査・評価と根拠、公開／保留、残課題・停止理由を受け取る。必要な役割と分離はその手順に従い、モデル設定は `.codex/agents/` を使う。
- 本文・関連リンク・出典を確定してから、対象wikiの公開条件を満たした記事だけをindexへ明示追加する。コマンドは `python3 tools/wiki/wiki_structure.py index --collection <id> --add <id>:<slug>`。既存記事の概要更新は `--add` なしで生成する。index更新はこの共通スキルが担当し、wiki側手順では重ねて実行しない。サマリは概要の最初の段落から生成し、別途執筆・短縮しない。既存カテゴリと公開済み項目を保持し、新規項目は必要なら分類先だけ調整する。
- 関連先からのリンクは理解に必要な場合だけ追加する。被リンクは `python3 tools/wiki/wiki_structure.py backlinks <id>:<slug>` で取得する。

入力、対象wiki、新規・更新・スキップと理由、実施した検査・評価、公開／保留、残課題を報告する。wiki側に報告schemaがある場合はその必須項目を保持する。検査の失敗や未実施を完了扱いしない。
