# $retrospect

セッション末尾に明示的に呼び出す。参照できる会話・実行結果から、次回の作業を改善する知見を抽出する。既定は報告と具体案の提示まで。全記事監査や過去セッションの一括収集、恒久的な振り返り台帳の作成は行わない。

## 根拠を集める

参照できる依頼・訂正、ツール結果、評価結果、作業報告から候補を拾い、確認に必要な差分・関連ファイルだけを追加で読む。既存の未コミット変更や過去の評価を、このセッションの成果・失敗と決めつけない。

- コマンド失敗、再試行、回避手段。回避後も元の目的と検証範囲を満たしたか。
- 探索の空振り、再読、手戻り、委譲や確認の過不足。通常の探索や有益な試行錯誤を、それだけで失敗としない。
- ユーザーの訂正、意図の取り違え。今回限定の要望を恒久的な好みとしない。
- 未実施・失敗した検査、未確認の仮定、残課題と完了報告の食い違い。
- 記事評価で見つかった欠陥と、手戻りを減らした工夫。

観測事実と原因の推定を区別する。内部思考を再現したり、見えない履歴を補ったりしない。履歴が圧縮・欠落している場合は確認範囲を明記する。根拠は会話中の具体的な出来事、コマンドと結果、ファイルの該当箇所など、後から識別できる形にする。

## 作業上の不備を報告する

未検証・未完了・誤報告があれば、改善提案の採否とは独立に報告する。対象、根拠、結果への影響、残っている対応を示す。解消済みか未解消かを区別し、誤った完了報告は訂正する。回避策で確認範囲が狭まっていれば検証不足として扱い、成功した手順として推奨しない。

改善効果が薄い、再発しそうにない、提案がゼロという理由で、現在の作業の不備を隠さない。参照範囲が足りない場合に「問題なし」と断定しない。

## 提案を選別する

候補の抽出とユーザーへの提案を分け、次の条件をすべて満たす候補だけを提案する。

1. **観測された効果・実害がある**：不要な再試行、手戻り、品質低下、または工夫による改善を具体的な根拠で示せる。
2. **次回にも効く**：再発・再利用する条件を説明できる。反復回数は固定せず、一度でも影響が大きく再発可能なら対象とする。
3. **変更が原因に効く**：変更先と、次回変わる判断・行動を具体化できる。「注意する」「よく確認する」だけでは採用しない。
4. **追加負担に見合う**：毎回の読込・確認・保守の負担を含めても、減らせる失敗や作業に見合う。

「この変更が当時あれば何を防げたか、または何を再現できるか。その代わり今後どんな負担が増えるか」に答えられない候補は落とす。数値根拠のない効果見積もりや点数付けはしない。

一時障害だけを根拠にした恒久的な回避手順、既存ルールの重複、わずかな省力化のための毎回の確認追加、記事一件の表現修正からの一律禁止は原則として提案しない。既に解消した原因への追加対策も、残る必要性がなければ落とす。追加よりも既存手順の修正・削除・簡素化で済まないかを検討する。

## 正本と照合する

採用候補に関係する既存の手順・ルール・ツールを確認してから変更案を確定する。保守対象は [保守案内](../../../docs/maintenance.md) の対応行から読む。

記事の問題では [登録一覧](../../../wiki/collections.toml) → 対象 `wiki.toml` → schema・該当workflow・指定された基準のうち、原因判断に必要なものを読む。次を切り分ける。

- ルールがない：対象wikiの基準に必要な判断条件を追加する候補。
- ルールが読まれていない：スキルやworkflowの読込経路を修正する候補。
- 適用を誤った：曖昧な判断条件や例を明確にする候補。
- 機械的に検出できる違反が漏れた：既存の検査ツールを改善する候補。
- 記事固有の問題：記事修正にとどめ、共通ルールへ一般化しない。

共通スキルへwiki固有の品質基準を複製しない。振り返りを独立評価の代わりにしない。

## 出力と適用

作業上の不備があれば先に示す。続いて採用した提案だけを、効果と必要性の高い順に示す。各提案には「観測事実と根拠」「原因の判断」「具体的な変更案と変更先」「期待する効果・追加負担・確かめ方」を簡潔に含める。件数目標は設けず、該当しなければ「今回は提案に値する改善はありません」とする。不採用候補や根拠不足の様子見リストは、求められない限り並べない。

適用も依頼されていれば、既に認められた範囲を再確認せず進める。運用・ツール変更は保守案内、記事変更は [$review-page](../review-page/SKILL.md) の対象wiki手順に従って変更・検証し、実施結果と残課題を報告する。独立評価など必要な工程を省略して完了扱いにしない。
