# $query

## 検索と回答

1. `wiki/collections.toml` から設定を見つける。対象指定があればそのwikiだけを選び、未指定なら各設定の `purpose` と検索結果で候補を絞る。
2. 設定の `index` と `pages` を `rg` で検索し、関連する記事を読む。常に全indexを全文読込せず、関連リンク・他wikiへ必要に応じて範囲を広げる。ユーザーが範囲を限定した場合はその指定を守る。
3. 記事だけで質問の核心に具体的に回答できれば、その根拠から回答する。記事不足、情報の曖昧さ、最新情報の必要があればWebで補完する。引用元はファイルリンクまたは `[[<wiki-id>:<slug>]]`、Webは確認したURLで示し、wiki由来と補完・推論を区別する。

設定内のパスは設定ファイルのディレクトリ基準。検索対象は記事とindexとし、設定・手順・評価履歴を知識記事として混ぜない。採用・執筆・評価文書は通常の回答では読まない。被リンクはルートで `python3 tools/wiki/wiki_structure.py backlinks <id>:<slug>` を実行して取得する。

広い検索は `finder` に範囲と根拠抽出を委譲できる。単純な照会では子を必須にしない。根拠の競合や複雑な統合が結論を左右する場合は `evaluator` に質問・草稿・根拠だけを渡し、未支持の主張、因果・階層、見落とした問いを独立検証させる。以前の判定・結論を渡さず、回答検証を記事評価の代わりに使わない。

## 追加の提案

新たな知見、既存記事の重要な補強、意味のある新接続がある場合だけ提案する。単なる言い換え、独立した知識にならない回答、既に記録済みの内容は提案しない。提案時だけ候補wikiの設定が指す `workflows.ingest` の採用判断部分と、そこで指定されたschema・採用基準を読む。執筆・評価段階の参照文書はこの時点では読まない。対象wiki、新規／追記先、理由、追加内容を示す。

query自身は記事・index・関連先を書き換えない。追加が承認されたら、参照ソース、得た知見、対象wiki、新規／追記案を `$ingest` へ渡し、対象wikiの必要な調査・執筆・評価・公開手順を実行する。既存の追加承認は再確認しない。

回答、根拠、必要なら追加提案を報告する。wikiと外部情報に矛盾があれば明示する。回答の質を落としてまでwikiへ内容を詰め込まない。
